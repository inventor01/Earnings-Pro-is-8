- First Android build succeeded Aug 3, 2026 (EAS profile `preview` = APK; `play` = app-bundle for Play upload). Signing keystore is EAS-managed cloud (auto-generated) — never local.
- Same EAS invocation rules as iOS: `GIT_CEILING_DIRECTORIES=/home/runner/workspace EAS_NO_VCS=1`, sed package-firewall from lockfile first.
- Android billing is LIVE (user-confirmed paywall works, Aug 8 2026): `goog_` key baked in eas.json, Play products created via the androidpublisher API (subscriptions: pro_monthly/monthly $2.99, pro_yearly/yearly $29.99; one-time pro_lifetime $79.99 via lowercase `/onetimeproducts/{id}?allowMissing=true` PATCH — the camelCase create path 404s). Creating paid products requires the developer account's payments profile to exist first (FAILED_PRECONDITION otherwise). RC has the Play service-credentials JSON uploaded. Free-trial offers (`freetrial`, P1W free, new-subscriber) live on both base plans — offer creation needs offer-level `regionalConfigs`+`otherRegionsConfig` availability blocks, not just phase configs, or it 400s ("must target at least one region").
- User has a Play Console account (earningsninjaapp@gmail.com, created Aug 2026, personal → expect 12-testers/14-day closed-test requirement). User has NO Android device — verification is via Play internal testing / borrowed devices.
- Gap report: `docs/android-gap-report.md`. iOS widget has no Android counterpart; don't mention widgets in the Play listing.
- Play uploads are automated (Aug 8, 2026): service-account key at `earnings-ninja-expo/credentials/google-play-service-account.json` (gitignored; from GOOGLE_PLAY_SERVICE_ACCOUNT_JSON secret), `eas submit --platform android --profile play --id <buildId>` pushes to the internal track. A duplicate-versionCode error means that version is ALREADY on Play — check the track via the androidpublisher API before assuming failure. Bump `expo.android.versionCode` before every Play build.
